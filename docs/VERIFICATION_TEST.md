# Secret MCP Reverification Record

## Purpose

Verify that the following behavior can be reproduced from a fresh clone of the public repository.

- Dependency installation and security audit
- TypeScript build and ESLint validation
- Exclusion handling for GDWEB search results
- Creation of separate MCP sampling requests for every search result
- Storage of per-result `DESIGN_INDEX` documents, request contracts, evidence images, and the run manifest
- Startup and browser rendering of the Design Index Viewer

## Fresh-Clone Procedure

The first `npm ci` completed the installation but reported one moderate-severity vulnerability in `sanitize-html 2.13.1`. The issue was [GHSA-vccv-cmxp-4j9h](https://github.com/advisories/GHSA-vccv-cmxp-4j9h), which concerns incomplete URI-scheme validation.

`sanitize-html 2.17.6` requires Node.js 22.12 or later, which is incompatible with this project's Node.js 20.19 support range. The dependency was pinned to the exact version `2.17.5`, which contains the vulnerability fix without imposing the higher Node.js engine requirement.

```bash
npm install --save-exact sanitize-html@2.17.5
```

## Live Food-Reference Scenario

Following the user scenario, three food-domain references were selected from GDWEB award winners registered in 2025 and 2026, and every work was analyzed by a different independent LLM task.

| Reference ID | Work | Evidence Images | DESIGN_INDEX | Independent-Task Result |
| --- | --- | ---: | ---: | --- |
| `gdweb-26387` | Yeong Coffee | 3 desktop | 1,020 lines | No other Reference ID |
| `gdweb-26788` | Yorien | 4 desktop, 1 mobile | 869 lines | No other Reference ID |
| `gdweb-26853` | Ggublack Chicken | 7 desktop, 1 mobile | 1,690 lines | No other Reference ID |

Each of the three tasks received only its own work's request contract and image evidence. Every document contains all 19 required sections: the page and route inventory, shared shell, navigation, per-page coordinates, section deep dives, components, HEX/RGB/HSL colors, typography, assets, the `1440/1280/1024/768/390/360px` responsive matrix, interactions, accessibility, data model, architecture, task graph, per-page QA, and uncertainties.

While preparing the large evidence images for `gdweb-26853`, the MCP SDK's default 60-second sampling limit was encountered. `MCP_SAMPLING_TIMEOUT_MS` was initially introduced at `180000ms`. The current runtime default is `1800000ms` because a strict multi-page `DESIGN_INDEX` now requests a `131072`-token per-work output budget.

## Acceptance Criteria

Verification passes only when all of the following conditions are satisfied.

1. `npm audit` reports 0 vulnerabilities.
2. TypeScript and ESLint exit with status code 0.
3. An excluded Reference ID is not included in a sampling request.
4. The number of works, independent sampling requests, and `DESIGN_INDEX` documents is identical.
5. No request contains another work's Reference ID.
6. The Viewer health API and initial page respond normally.
7. The Viewer browser console contains no errors or warnings.
8. Every document contains only its own Reference ID and does not mix in another work's ID.
